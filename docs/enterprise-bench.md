# Enterprise bench — what Quark can do today as an enterprise data layer

This is the numerator of the A8 gate ("Quark enterprise"). It exists because
that gate needs a number, and a number needs something that produces it.

**Measured on 2026-09-20 against v1.14.0, and kept current as the arc closes
its gaps: the numbers below are what the suite produced on its last run.** Run
it with:

```bash
go test ./internal/enterprisebench/ -run TestEnterpriseBench -v
go test ./internal/enterprisebench/ -run TestEnterpriseBenchSummary -v   # the totals
QUARK_BENCH_TABLE=1 go test ./internal/enterprisebench/ -run TestEnterpriseBenchTable  # regenerates the table below
```

The bench is not prose. Every control is a Go probe in
`internal/enterprisebench/` that opens a client and drives the public API,
reads the SQL the builder actually emitted through a query observer, or asks
for a capability and reads the error it gets back. `TestEnterpriseBench`
asserts the **recorded verdict** rather than success, so closing a gap turns
the suite red with "this one is present now, update the verdict" — which is
what keeps this page honest.

## Why the arc was measured before it was planned

A8 was written months before anyone looked at the code, and named three
things as future work: "declarative diff, `migrate diff`, plan hash". The
measurement found that two of them already shipped, and that the third does
not mean what the plan assumed — `Plan.Hash` is the key of the resumable
checkpoint, not a detector of a schema that changed under the plan's feet.

It also found that "RLS on three engines" assumes there is something on more
than one. There is not: native RLS is PostgreSQL and nothing else.

That is the rule rather than the exception. The three times an arc was planned
without measuring, the measurement corrected the plan.

## The verdicts

| verdict | meaning |
|---|---|
| **present** | the control exists, an application can reach it, and its probe exercised it end to end |
| **partial** | a piece exists; the case records exactly what is missing |
| **absent** | no surface an application can use — the probe measures the absence, never the lack of a grep hit |

A control that cannot be probed does not belong in the bench. A capability
that lives only in an internal package is not present either: an application
cannot reach it.

## What this bench can and cannot see

It runs on SQLite, in the root module, so `go test ./...` exercises it on
every change. That is enough to measure a surface, a contract and a refusal —
whether the builder can emit a clause at all, whether a capability is
reachable, what a dialect that lacks a feature answers. It is **not** enough
to certify behaviour against PostgreSQL, MySQL, SQL Server or Oracle. Where a
control needs a live engine to go further, its note says so, and
`internal/enginesuite` is where that proof lives.

## The result

**20 of 69 controls present. 28 partial. 21 absent.**

### migraciones — 5 present · 5 partial · 6 absent

| id | control | verdict | what is missing |
|---|---|---|---|
| `MIG-01` | Declarative diff: a desired schema is compared against the live one and applied, tables and columns only | **partial** | The loop does not converge. A desired schema carrying an index and a foreign key applies with a nil error and neither reaches the database, so re-diffing the same desired schema against the result proposes the same work again. Tables and columns do round-trip — the probe reads them back and classifies the residual, so a residual carrying table or column work answers absent instead of this partial. |
| `MIG-02` | A desired schema can come from a versionable document instead of compiled Go models, tables and columns only | **partial** | A JSON document deserialises into quark.Schema (every field is exported) and goes through quark.Diff and ApplyPlan with no Go model compiled in: its tables and columns reach the database. What it declares beyond them does not — the index and the foreign key in the document apply with a nil error and never arrive, the same half MIG-01 measures from a hand-built schema. PlanMigration is not the way in: it reflects over Go values, which is MIG-11's subject. |
| `MIG-03` | The plan built from models carries the index set (proposes creating or dropping indexes) | **absent** | The plan is identical with the index present and with it dropped. | `MIG-04` | Plan.Hash is a deterministic 64-character digest that separates plans that differ | **present** | — |
| `MIG-05` | Applying a plan detects that the schema changed between planning and applying | **absent** | The plan's digest is a function of its ops alone, so it does not move when the database does, and ApplyPlan re-reads nothing. | `MIG-06` | ApplyPlan is all-or-nothing on SQLite, and reports success for a CREATE TABLE it applied in part | **partial** | The rollback half holds: a failing second op leaves nothing of the first behind — and if it ever stops holding the probe answers absent, because that is the half this title publishes as a guarantee. Every delta is read back from the catalog, so a nil error that changes nothing counts as the gap it is. Whether the type path works elsewhere needs a live engine — internal/enginesuite. |
| `MIG-08` | Plan.Down derives a rollback, applies it, and refuses what it cannot invert | **present** | — |
| `MIG-09` | Reversible round trips beyond CREATE/DROP TABLE: column and index yes, foreign key no | **partial** | Add-column and create-index go to the database and back with the catalog agreeing. The probe keeps each round trip in its own variable, so this partial means exactly the two the title names; any other split answers absent. Proving the FK round trip needs an engine with ALTER TABLE ADD CONSTRAINT. |
| `MIG-10` | Distributed migration lock: refused on SQLite, and the versioned migrator runs anyway without it | **partial** | AcquireMigrationLock answers ErrUnsupportedFeature on SQLite, which a caller can act on. The migrator that asks for it by default degrades to running unserialised and reports it at Debug only — measured with a sink on the migrator's logger: the degradation line is there, at Debug, and nothing at Warn or above came with it. A migrator that refused, or that returned nil without applying, answers absent. The five engines that implement the lock need internal/enginesuite. |
| `MIG-11` | PlanMigration serves a binary that has none of the user's compiled models | **absent** | Planning with no models — all a precompiled CLI can pass — yields a plan that drops the live tables, because the desired schema is whatever Go values the caller supplies. | `MIG-13` | A plan can be rendered as the DDL of a migration file from the library | **absent** | The only rendering the library offers names the table and drops its columns, their types and its indexes, so nothing callable from Go can write a migration file. The CLI's `migrate create --from-models` does generate one, but it lives in the cmd/quark module, out of this bench's reach, and its emitted DDL is unbranched per dialect. WHAT the rendering drops decides this verdict: a rendering that carried the columns and their types and still dropped the indexes would be the half MIG-01 and MIG-02 call partial, and answers partial here. |
| `MIG-14` | Hand-written versioned migrations: ledger, dry run, up, down | **present** | The cycle needs the client the migration guide prescribes — AllowRawQueries enabled. Measured, not read: on a default-limits client Init and the migration body go through Raw() and are not refused, and the run fails at the LEDGER INSERT, which the migrator does through Client.Exec (ErrInvalidQuery, "raw queries are disabled by default") — after the schema change already happened. |
| `MIG-15` | Data backfill resumes where an interrupted run stopped | **present** | — |
| `MIG-16` | On SQLite the resumable checkpoint table is never created (ApplyPlan takes the transactional path) | **absent** | Measured here, on the one dialect this bench runs: after a successful ApplyPlan, quark_migration_state is not in sqlite_master.
